# Contributing

Install with `python -m pip install -e '.[dev,notebook]'`, then run `python -m pytest -q`.

For a numerical change, explain the mathematical change and its expected accuracy or stability effect. Add a test that distinguishes the corrected result from the previous behavior. Run the affected manufactured-solution studies and a cavity comparison; inspect the actual residual and convergence status. A new linear solver should agree with the existing backends within its tolerance.

Keep published reference values immutable in meaning. Document source tables, coordinate conventions and any anomaly flags in `docs/references.md`. Do not change reference numbers to improve a comparison. Report full and sensitivity metrics separately.

Figures and tables are generated by `scripts/build_results.py`. The notebook source is `scripts/build_notebook.py`. Rebuild both after changes to their inputs, and execute the notebook before committing its outputs. Inspect the compiled report visually after editing LaTeX. The full production suite is intentionally separate from CI.

Use the existing module boundaries: model inputs belong in `problems.py`; stencils and linear solvers in `operators.py`; integration in `solver.py`; analysis outside the stepping loop. Keep the default runtime independent of notebook tooling.
